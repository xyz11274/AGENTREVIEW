## 五、附：prepare-specialists 泄漏审计事件（2026-08-18 追加）

**现象**：prepare-specialists 报 `leakage_count=2265`（historical 1045 / validation 145），`passed=False`。

**定位**（已完整复现，POL 单任务复现出 193 条泄漏记录，机制与总数吻合）：

- audit 实现：`audit_candidate_visible_artifacts`（agentreview_data.py:388-459）+ `assert_no_human_reference_leak`（462-469），prepare 侧调用在 917 行，参考语料含 `_source_human_reference_corpus`（472-505，`source::<paper_id>::<index>` id 即出自此处）。
- 匹配方式：candidate record 内所有字符串按行切分（≥20 字符）与 reference 侧行集合**精确相等求交**；非子串、非 SRC 锚点。
- 成因：query 含论文 References 列表全文；CoCo `sentence_texts` 含 reviewer + author rebuttal 讨论句，其中被逐字粘贴的引用行与论文参考文献行整行相等。audit 不按 paper_id 限定、不扣除 candidate 合法可见的论文自身文本 -> 跨论文（共享引用行）与同论文（rebuttal 引用自己参考文献）双重误报。

**判定**：**false positive**。全部命中 fragment 均为论文自身参考文献行或学术套话，抽样 5 条的 POL evaluator reference 全为空，无任何 reviewer 意见/评分/meta-review 文本进入 candidate-visible 侧。非 Human Reference Boundary 违规。

**建议修复（未实施）**：① reference fragment 集合先扣除"出现在任一 allowed 论文 canonical 文本中的行"（根本修复，泄漏定义应为"candidate 无法从合法输入推导出的文本"）；② 比对按 paper_id 限定；③ 语料收集复用 reviewer-role 过滤。注意 formal_protocol.py:241 复用同一函数，需一并修。

### 5.1 2026-08-19 落实：复用 CoCo 数据面与官方 reference 程序

进一步核对 CoCoReviewBench 后，需澄清“已剔除 human review 数据集”的准确含义：

- CoCo 的 Candidate/AI-reviewer 入口读取 benchmark record 的 `id/MD_path`，实际模型输入是 paper Markdown；它不是从含 human review 的 JSON record 中做字段删除。
- `benchmark_left_out_human.jsonl` 保存的是被留作 human baseline/test reviewer 的文本及 reviewer selection，本身不是 Candidate paper dataset。
- evaluator gold 仍由原始 benchmark 的 `reviews/sentence_texts/opinions/opinion_groups/conflicts_validation/rebuttal_validation` 构建。
