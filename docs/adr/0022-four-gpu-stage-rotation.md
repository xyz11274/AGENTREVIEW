# ADR-0022：仅使用 0–3 号 GPU 的阶段模型轮换

2026-09-17 用户明确选择“四张卡，按阶段轮换模型”，随后将分配更正为 **0–3**；4–7 不再供本实验使用。覆盖此前三服务常驻和跨模型阶段重叠的部署选择，保留全部科学协议、论文清单、模型权重精度、输出预算、模型生成温度、thinking、MSTAR 随机状态与失败预算。

部署入口 `deployment/four_gpu_study.py` 在原冻结入口之外增加有明确文件哈希的部署附录，不改写已冻结的算法文件或历史结果。所有角色、Meta、反思、记忆构建与 Native 的生成 client 完整生命周期持有 reviewer 模式；原版 CoCo 的整个 Split、Classify、Judge worker 阶段分别持有对应模式。只有当前模式全部退出，才能停止旧模型并启动下一模式。同模式的两个论文任务可以并行，排队中的其他模式不会被新生成任务无限推迟。

| 模式 | GPU | 上下文 | 精度 / TP |
|---|---|---|---|
| Reviewer / Memory / Meta / Reflector / Native | 0,1,2,3 | 131072 | 原 BF16 / TP4 |
| CoCo Split | 0,1 | 65536 | 原 BF16 / TP2 |
| CoCo Classify | 0,1 | 32768 | 原 BF16 / TP2 |
| 原版 CoCo Judge | 0,1,2,3 | 65536 | 原 BF16 / TP4 |

生成端和 Judge 共用端口 18001，但使用两个显式模式。现有 `development_coco_worker` 对 Judge 的原部署契约严格要求 65536；生成端为了完整论文与 Meta 使用 131072。此前同一个 131072 常驻服务无法通过这个原始评分端检查，本次轮换让两种服务分别满足其既有契约。Judge 的 32768 输出预算、Split/Classify 请求设置以及原评分算法没有变化，也没有放宽收据检查。

阶段切换在原请求/CoCo 阶段重试预算预留之前进行，等待模型加载不冒充逻辑请求失败；加载失败按公共依赖失败暂停，不增加候选质量失败次数。不会量化、CPU offload、裁论文、缩短输出、将失败记为零或绕过原版 CoCo 的真实进程身份和前后 PID 一致性检查。四卡顺序轮换会增加加载耗时，停止原先跨模型的重叠。

安全迁移：只向原控制器发送 SIGINT，让已在执行的论文 worker 完成；20 份角色评审及 20 个完整请求已落盘，没有未结束的逻辑请求，候选失败和修复计数仍为 0。然后定向停止原已登记服务并核实 4–7 显存释放。恢复时沿用原搜索目录、请求缓存及随机流；不从头重跑 build。

验证包含模式互斥、同模式并发、公平排队、加载失败不启动请求、异常释放、GPU 白名单及调用参数原样传递；另执行一次真实四模式部署启动/释放检查，使用原 CoCo worker 的服务身份检查器核验端口进程、模型路径和上下文。这是部署生命周期检查，不是新增论文 pilot、评分调参或模型质量试验。

部署切换耗时、当前模式、模式等待及加载状态保存在 `deployment-minimum-cards/rotation`；原实验逐阶段耗时及服务遥测继续保留。旧七卡配置只是被用户否决的未执行提案，实际运行只绑定四卡配置与部署附录。
