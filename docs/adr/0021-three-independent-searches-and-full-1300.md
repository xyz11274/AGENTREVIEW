# ADR-0021：三次独立共享搜索与原 1300 篇配对评价

2026-09-17 用户明确确认。本协议覆盖 ADR-0019/0020 中旧的最终样本排除规则和未确定的搜索数值；保留其修复、原版 CoCo、五角色和逐论文状态隔离规则。历史产物不改写。

## 数据与对照

复用原 build 125 / static 25 / rotating 125，论文 ID、顺序及正文均与核实后的原划分相同。最终评价使用原始抽样清单的全部 1300 篇；包括有既往开发用途的论文和失败案例。已知用途另存标注，用于完整样本的诊断分层，不自动排除，不宣称严格未见盲测。不同论文版本的跨分区重叠检查继续执行。测试参考仅交给 CoCo，测试结果不得反馈进化、调参或挑选某一次搜索。

三次搜索随机种子为 `[0, 1000, 2000]`。每次从修复后的 Vector Search、LLM Summarizer、Experience Learner 三个原始程序建立自己的 build 经验、角色记忆、候选池、请求记录、轨迹和失败账本。不继承 pilot 的候选、经验库或反思历史。只共享无状态且有内容及模型身份绑定的 embedding 编码缓存。

每次搜索有 20 个进化尝试预算；成功、重复提案和最终失败均占一次尝试。重复源码提案保留其父代哈希及独立结果，不改写 pilot 历史。static 25 篇的完整原始 `Paper.` 用于入池、父代抽样和 Champion 排名。有效低分照常入池。

每轮对父代抽取 5 篇 rotating，使用该轮独立请求目录重新生成完整评审并运行原版 CoCo。按 `Paper.` 从低到高选两篇详细反思，同分时用独立随机流打破平局；保留其余结果概况、所有 5 篇完整评分与五角色原始轨迹。两个选定完整案例超出反思输入预算时明确失败，不切文本或偷偷替换案例。

每次搜索分别评价八个冻结系统：三个固定 Memory 种子、三个匹配无记忆对照、Native、该次 Champion。三个搜索及 Champion 开发终评全部完成后发布统一冻结收据，才开放最终 1300 篇。因此计划最终有 3 × 8 × 1300 次论文级系统评价；不得只报告测试最好的搜索。逐篇配对差值、均值、按论文家族 bootstrap 的不确定性、三次 Champion 间差异、失败原因和有效评审/小时分别报告。

## 温度与可恢复随机性

父代 softmax 直接输入原始 1–5 `Paper.`，温度为 **0.6**。不先归一化再使用 0.6，也不重复除以 4。归一化 `(score-1)/4` 配 0.15 的权重等价性有回归覆盖。生成温度、thinking、CoCo 评分和 Champion 排名不因这个采样参数改变。

父代选择、rotating 抽样和反思案例选择分别以 SHA-256 派生 Python Random 随机流。每个决定与更新后的随机状态在同一搜索 checkpoint 原子写入。恢复复用已经提交的决定，不重置随机状态或预算；共享评分故障触发新评价 epoch 时，旧反思案例决定另行保留，再按新完整反馈选择。

## 失败事件与计数

| 事件 | 规则 |
|---|---|
| AgentReview 逻辑模型请求 | 持久账本最多 3 次实际调用，SDK 重试为 0，外层不得再次放大；恢复仍使用原账本。原版 CoCo 自身重试不变 |
| 候选契约失败 | 每个候选至多额外修复 1 次，修复记录保留 |
| 候选最终失败 | 原始尝试及允许的修复仍失败后，按唯一事件计一次；不入池、不补零 |
| 连续最终失败 | 连续 3 个暂停诊断；只在有新原因、修复和验证凭据后恢复，不清空累计计数。合格候选打断连续失败计数 |
| 累计最终失败 | 5 个结束该搜索，保留结束原因、实际尝试数和已验证的最佳有效 Champion；不伪称完成 20 个尝试 |
| 整次修复 | 累计上限 10 次，包括候选修复及经验证的人工/共享故障干预。第 10 次可以完成，不能分配第 11 次。重复恢复同一凭据不重复计数，新暂停不能复用旧凭据 |
| 公共服务故障 | 暂停诊断，不增加候选质量失败数；恢复沿用既有重评规则和累计修复账本 |
| 不完整生成或评分 | 阻断后续汇总、评分、入池及发布；原定样本保留失败记录，分数为空，不填零 |
