# 冻结 no-memory Review Corpus，完整 Review 为权威记录，检索视图确定性派生

状态：accepted（2026-08-27）。本 ADR supersede ADR-0002，并部分 supersede ADR-0005 的“共享题目、不共享 AI review”边界及 ADR-0007 的 A 区 sequential self-generated replay 语义。

后续主实验先由统一、冻结的 no-memory Reviewer 在 A 区论文上生成共享的 **Full Review Corpus**，再让所有 MemoryProgram 在相同 Review 输入上进化存储、检索和使用策略。五个 Specialist 的职责和 prompt 不同，因此 `QUAL`、`CLAR`、`SIGN`、`ORIG`、`POL` 分别生成并冻结自己的 role-specific Corpus，不共享一份 general review。真人 review、gold opinion、CoCo taxonomy 与 evaluator 输出仍不得进入 Corpus。该选择把当前研究归因收窄为“固定审稿经验上，Memory 策略及其 Evolution 是否改善 held-out Review”，换取更清晰的单变量归因和可复用的 A 区资产；完整 Harness 自产经验另列后续实验，不与本主线混称。

每篇完整 AI review 作为不可变 **Full Review Record** 保存并按内容哈希锚定。Canonical payload必须按role registry canonical order完整包含全部固定subdimension sections；缺失、重复、额外或乱序section经过一次identical retry仍非法时Corpus build fail-fast，不使用whole-review fallback。向量检索单元只是可重建的 **Retrieval Projection**：每个固定section产生一个primary projection，仅在超过冻结token上限时无overlap地确定性二次切分，并保留paper、role、subdimension、原文位置和Review SHA。不得使用 CoCo/gold 分类结果为 Candidate Memory 打标签。

主实验中每个 A paper × role 只产生一份 canonical Full Review Record。模型 revision、reviewer prompt SHA、temperature、generation budget 与确定性验证规则在 Corpus 生成前冻结。所有 raw attempts 均保存，第一份通过协议验证的输出成为 canonical record；最多允许一次按同一冻结 retry protocol 的 Reviewer LLM 重试。两次均失败时 Corpus build fail-fast，不得跳过该 paper 或用缺失样本继续。多 Corpus replicate 只能作为独立 robustness 实验。

运行期删除独立、隐藏的生成式 `Memory Query` 与 `KnowledgeItem` 服务。统一Review Memory API及query construction、vector search、filter、top-k、hydration decision、rerank与semantic filtering全部保持model-free、deterministic且可重放。唯一例外是明确注册的 `LLM Summarizer`：它可以在确定性retrieval已经完成后，经统一Qwen scheduler对当前paper已合法返回的Memory执行query-focused summary/condensation；该调用不得改变或补充召回集合、similarity、ordering或top-k，不得读取未返回Memory，也不得写回Corpus、Projection、Index或跨paper persistent Memory。除该注册行为外，其他Program不得使用retrieval-side auxiliary LLM；未来扩展必须发布新protocol/capability version。Review Projection与index materialization本身保持无LLM、确定性。Reviewer LLM继续生成实际review，Evolution Reflector LLM继续产生child MemoryProgram；Embedding不属于生成模型，可按冻结revision批量预计算和缓存。

Full Review、Primary Projection与Projection Fragment分别使用`fullrev_`、`proj_`与`frag_`前缀的domain-separated完整SHA256 identity。V1索引使用normalized float32 embeddings上的deterministic exact flat inner-product与稳定ID tie-break，不使用ANN或rerank。每次retrieval/hydration先durable commit immutable `RetrievalResultManifest`，注册Summarizer只能消费该manifest确定性装配的内容；非空`stop/length`均成为canonical summary，空响应或backend故障按infrastructure failure处理，禁止silent fallback。Review Memory预算按API calls、delivered fragments、full-record hydrations、delivered tokens与top-k五个维度在materialization统计后预注册，并对全部initial seeds与descendants一致。

新formal发布`Vector Search v2`、`LLM Summarizer v2`与`Experience Learner v2 / Structured Experience Recall`三个新Program；旧canonical seed key只保留birth ordering/provenance，旧identity与fitness不得混合。Program以closed `memory_read_mode`而非lineage获得least-privilege capability；mode可随child改变但必须产生新Program identity并重新gate。Experience Learner v2删除生成式KnowledgeItem，改为确定性组织原始retrieved review text。每个paper使用fresh Review Memory/Summarizer session，B paper不得写回Memory或把query/ledger/summary状态带入下一篇。

Review Memory API采用atomic budget：成本超限时整次拒绝、不partial delivery或runtime truncation，失败探测消耗API call但不消耗delivery额度。成功deliveries按occurrence写入append-only ledger，重复读取保留且重复计费；Summary每paper最多一次，manifest包含全部ledger occurrences。Summary input/output budget在materialization/gate后预注册，input超限时不dispatch、不裁剪manifest、不重试也不fallback。

Memory API预算通过独立`MEMORY_BUDGET_TRANSITION_COMMITTED`进入事务边界；success、budget exhaustion与Candidate invalid request的response和预算转换必须先commit，成功delivery还须commit ledger occurrence，之后结果才对Candidate可见。冻结truth table区分success实际成本、非call exhaustion仅call+1、invalid request仅call+1、call饱和no-op与infrastructure无transition；每个response只能绑定一个transition。恢复只复用已提交response补完transition/ledger，禁止重复API执行或计费。Reviewer Memory context拆分为non-self-hash authoritative payload/envelope与独立SHA的唯一visible projection：Reviewer request绑定并验证双SHA，但prompt仅含冻结framing、必要非语义provenance和context text，Candidate/内部SHA/budget/audit字段不可见。Direct保留全部ledger occurrences；Structured Experience按role subdimension、source首次出现、record内occurrence三级顺序组织，保留重复且不改写/总结/选择。Hydrated Full Review每occurrence只计费一次，各section与可选overall在冻结位置恰好展示一次；Summary只交付canonical summary与非语义provenance。Summary input超预算属于Candidate-originated failure；合法empty ledger则产生显式empty context并正常Review。

Reviewer-visible source provenance采用最小closed集合，只含occurrence ordinal、source A-paper manifest ID、role、content kind、subdimension/role-overall标记及paper anchors；similarity、query、top-k、budget、ledger/request/Candidate/internal SHA均不可见。完整visible projection另受预注册`max_reviewer_memory_context_tokens`约束：Direct/Structured由Candidate retrieval导致超限时Candidate failure且不裁剪/fallback；Summary max-output与最坏合法framing/provenance必须在preformal证明可容纳。Structured formatter为每个section/overall生成audit-only、non-billable `StructuredViewItem`，验证原始bytes与恰好一次展示；该identity不是新的Memory asset或delivery。

Visible `content kind`闭集为`PROJECTION_FRAGMENT / PRIMARY_PROJECTION / FULL_REVIEW_RECORD / FULL_REVIEW_SECTION / FULL_REVIEW_OVERALL_ASSESSMENT`。Record kind只用于Direct/Summary的单次hydration occurrence provenance；section/overall kinds只用于StructuredViewItem，不能把一次hydration拆成多次delivery。Fragment只展示显式fragment anchors，继承的section anchors保持audit-only；projection/section展示完整section anchors，overall为空。Summary按ledger顺序保留每个重复source occurrence的最小provenance，只表示Summarizer输入集合，不声称逐项覆盖。统一Memory-context cap取所有formal paper×role在max-model-len中扣除完整non-Memory输入、Reviewer max-output与冻结reserve后的最小headroom，覆盖chat template/special tokens且formal中不按paper/role/mode变化。技术minimum只用于确保合法payload可执行，不强制任何Candidate检索或使用非空Memory。Safety reserve待materialization/accounting/near-max gate后以非负整数和完整依据manifest冻结；token-count mismatch必须修复identity，不得用reserve掩盖。

Summarizer authority正式命名为`CanonicalSummarizerInputRecord`并使用`suminput_ + full SHA256`；唯一model输入是独立SHA的`SummarizerVisibleInputProjection`，旧`CanonicalSummarizerInputProjection`只作migration alias。Visible bytes只含冻结framing、按API-call顺序且产生正式delivery的重复exact index queries、按ledger顺序的全部重复deliveries及最小provenance；failed/zero-delivery query、authoritative audit、独立paper/STRUCTURAL通道、External Evidence、similarity/rank/budget/internal SHA均不可见。所有Programs共享query per-call/total limits，禁止index短query而Summary扩展。Summarizer-input gate使用独立`max_summarizer_input_tokens`覆盖eligible queries、raw Memory、framing与provenance；Reviewer-memory gate只覆盖Summary max-output、Reviewer-visible provenance与framing，二者禁止混用。字段长度与最大occurrences产生worst-case vectors；local rendered token count必须与backend `prompt_tokens`在五role/cold-warm/三次重复中严格相等，否则preformal fail。

Canonical query采用nonempty UTF-8 byte-preserving validation only，不执行任何Unicode、line-ending、whitespace、case或semantic rewriting；raw/canonical bytes合法时完全相同，并同时用于Embedding与eligible Summary input。Per-call query以Embedding tokenizer计量，累计Summary query以Summarizer tokenizer计量；同一bytes保存两套token IDs/count，禁止互换。Per-call超限是pre-search Candidate invalid request；仅Summary mode在materialization检查eligible successful queries累计上限，超限按`SUMMARY_INPUT_BUDGET_EXHAUSTED`与Q195处理，Direct/Structured不受累计limit影响且不得通过删改query fallback。

Query identity绑定逻辑string的strict UTF-8 bytes而非JSON wire encoding；Embedding service对decoded query重新编码并提供observed SHA，与committed canonical SHA不等即infrastructure/protocol failure且vector结果不可用。Summarizer直接复用committed bytes。每个产生delivery的成功vector-search call恰好一个query occurrence，multi-fragment/get/hydrate不复制；相同query的独立calls保留重复。Query与retrieved Memory以冻结length/delimiter framing作为untrusted quoted data，不能覆盖system/task或获得额外信息/capability；为保持bytes，不做semantic instruction stripping，其行为影响属于显式Program策略。

Query content使用`memqry_ + full SHA256`，相同bytes共享；每次call使用绑定Candidate/paper/role/Program/call ordinal的独立`memqocc_`，visible prompt不暴露两类ID。Summarizer framing以冻结ASCII header声明UTF-8 byte length并按length读取payload，不依赖结束delimiter；system与untrusted data保持物理role隔离，delimiter-like/多语言/CRLF/control-character vectors必须通过。Observed-query mismatch在Memory API response/budget前触发共享Embedding infrastructure stop/restart/replay，不消耗attempt或budget；只能以相同Runtime Identity恢复，否则受影响role fail-fast。

每个query vector形成绑定memqry、Embedding Semantic/Runtime Identity及canonical float32 vector bytes的`qemb_` QueryEmbeddingRecord；qemb是排除paper/Candidate/role/Program的内容身份。不同paper独立计算可产生相同qemb，但必须各自具有paper-local execution chain，相同ID不表示或允许cross-paper reuse。每个memqocc一一对应独立logical Query Embedding request并引用实际qemb；cache hit以显式terminal disposition完成，不产生transport attempt但不能省略request、call、budget或audit。Cache仅在同一Candidate×paper×role×Program与完全相同Embedding identities内复用，命中不改变ledger/result/scheduler/fitness。Summarizer request严格为一个冻结system message、一个只含length-prefixed visible projection的user message及chat-template generation prompt；禁止其他roles、history、prefill或Candidate控制boundary，完整messages/prompt/template/config进入Semantic Identity。

Query Embedding采用raw-response-first事务：每次实际调用依次durable commit dispatch、包含原始service response/observed-query SHA/provenance的response record，以及验证通过后的canonical qemb record。Recovery优先复用committed raw response，只有dispatch无response时才重发；非法response保留audit但不得产生qemb、Memory API response或budget transition。Paper terminal event关闭对应cache capability，既有records转为audit-only；下一paper即使memqry相同仍须重新执行Embedding事务。Formal batch按8→4→1选择，并要求同一真实query在全部合法real-item occupancy、partial/full batch、padding数量/tensor positions、cold/warm及三次重复中canonical little-endian float32 vector bytes完全一致；确定性padding/full-batch策略必须进入Runtime Identity，`1e-6`与top-k一致仅作诊断。Padding output自身不要求跨运行byte identity，只要求cardinality、mapping、dtype、dimension与finite-value结构合法并确定性丢弃。

Query Embedding logical request与每次item transport attempt使用独立identity；attempt绑定committed global epoch与epoch-local index。`EMBEDDING_SERVICE_EPOCH_COMMITTED`在initial preflight后提交0/previous null，same-Runtime restart/preflight后递增，dispatch必须引用current event。Ordinal只由durable event连续消耗：preflight无event时重做并复用next ordinal，controller-only crash复用committed epoch，service restart强制new epoch，logs/PID/temp无权影响。Request仅在actual dispatch消耗epoch；下一epochdispatch无论fault责任都消耗recovery，需要第三epoch时仅所属role fail-fast。Recovery保持FIFO但重组batch。Logical terminal闭集保持RECORD/CACHE_HIT/ABANDONED。

Batch validation与qemb生效采用两级all-or-none barrier：不可拆分的self-contained BATCH_RESULTS event内嵌有序完整records及canonical vectors。Vector JSON固定RFC4648 padded Base64、无whitespace/URL-safe variant/compression，保存length/SHA，real items按tensor position排序且padding排除；parser重验Base64、float32/dimension/SHA/finite。`qembbatch_`纯内容projection的每个item只含tensor position、qemb与canonical QueryEmbeddingRecord，排除batch/request、paper/role/Candidate/Program、epoch、validation与Journal execution bindings；外层连续Scheduler Journal event保存完整execution chain并单独授予commit。Preformal冻结最大event bytes、durability/crash gate及实测latency threshold，formal不得拆分、外置或切换representation。

相同qembbatch不允许formal dedup：每次execution提交独立self-contained event，projection引用自身确切event SHA。Canonical event/envelope不含prior-identical lookup；commit后可生成具有稳定`dedupobs_`内容身份的non-authoritative `BatchContentDedupObservation`，其prior集合以current Results event位置为固定prefix cutoff，后续events不得修改。Observation不进入chain/formal identity/recovery/workflow且缺失/失败/冲突无影响。Physical dedup不可见，自包含读取恢复不得依赖它。

Batch-results materialization固定primary加same-identity retry，`matatt_`使用closed terminal disposition；results event先于success，崩溃只补success，失败terminal与已commit event并存为integrity failure。失败顺序为terminal→cutoff→non-formal preflight→RECOVERED→retry；retry成功event→success，失败terminal→new cutoff。其他attempt保持paused、同identity、single-owner，不消耗retry。Materializer恢复不改service epoch；post-cutoff response永久audit-only且actual dispatch不回滚。Authoritative非法event仍是Journal integrity failure。

每个Results event唯一绑定commit时合法、未terminal且未消费的originating `matatt_`与唯一OUTPUT_COMMITTED execution/output SHA；materialization cutoff最多一个open instance，RECOVERED显式引用该failure与preflight且不得嵌套。Execution恰一OUTPUT或ABANDONED terminal；cutoff后late output只作audit，cutoff前output可直接恢复。Batch dispatch commit后round-robin cursor立即推进，后续failure/restart不得回滚。成功role/Suite在seal前提交authoritative artifact catalog。Compatibility使用proposed composition、`compatplan_`与ordered `compitem_`避免循环；逐项最多primary加一次retry，semantic mismatch不early-stop，完整COMPLETED后才决策且此前操作者看不到semantic diff。

Execution以matexec绑定ordinal/runtime，matdec先于self-contained matout。Audit Quiescence使用pre-head、唯一commit slot与closed Requirement Registry；Readiness和Export Access由独立single-writer infrastructure journals管理连续epoch。Export按TEB candidate、Access PASS、nonsemantic promotion三层授权；Final Suite绑定稳定九slot gate identities，NOT_READY影响范围由冻结Dependency Closure Registry机械计算。可信Replay Audit FAIL仍导出真实Export，未知Readiness不得越过gate。Target Controller implementation必须精确相同。

第三epoch只fail owning role。Scheduler cursor是固定role序上的next-role index，仅batch dispatch commit更新；旧run seal/drain后，`ROLE_RUN_SCHEDULER_ADMITTED`在不reset cursor、不抢占batch/order下授权下一正常role轮转。Compatibility正常路径为PLAN→STARTED→全部item terminal→COMPLETED→PASSED/FAILED，fatal路径以ABORTED替代COMPLETED并只能FAILED；二者互斥。STARTED前只有未读旧payload的deployment问题可在不改Plan下修复；Plan/Catalog不可验证、mismatch或tool/gate无可信结果均关闭保留路径。Semantic operands/results只在冻结Trusted Execution Boundary内最小授权可见，operator只看到非语义closed status。Suite引用PASSED event SHA；lifecycle不进入Evolution反馈。

Deterministic padding使用protocol-generated `embedding_padding_item_id`，绑定冻结payload、tensor position、policy和schema/version。它不是memqocc、logical/item attempt、Memory API call、Candidate budget、ledger、cache或qemb；output只参与cardinality/position validation后确定性丢弃。全部padding行为进入Embedding Runtime Identity。

独立Embedding scheduler按五role固定round-robin与role FIFO装配batch，partial batch仅在冻结`max_batch_wait`后dispatch，禁止query/content/cache/Candidate/fitness/runtime-aware重排。Batch wait从首个dispatch-eligible request进入空assembly buffer开始，以冻结monotonic clock计时，至batch-dispatch durable commit结束；restart恢复出的既有waiting requests视为wait已到期，preflight后立即按冻结顺序重新assembly/dispatch。Paper进入terminal前禁止新intent；正常完成须drain全部logical requests，failure关闭则为未terminal requests提交`QUERY_EMBEDDING_ABANDONED`。Paper terminal event是唯一cache-close authority，abandoned/late response不得生成qemb、修改ledger或重开cache。

## Considered Options

- **每个 Candidate 从 empty Memory 顺序重放 A 并自产经验**：不再作为下一阶段主实验；它把经验生成与 Memory 策略耦合，重复消耗大量 Reviewer LLM，并扩大归因范围。
- **共享 human/OpenReview review**：拒绝；违反 Human Reference Boundary。
- **共享冻结的 no-memory AI review，确定性构建派生索引**：采纳。

## Consequences

- A 区 Full Review Corpus 成为带 manifest、模型/revision、生成参数、源论文身份与 SHA 的冻结实验资产，不再为每个 Candidate 重复生成。
- 五个 Specialist 共享同一 A paper manifest 和生成条件，但分别持有 role-specific Full Review Corpus。
- Corpus manifest 必须同时锚定 canonical record 和全部 raw attempt；任一 A paper × role 缺失都使该 Corpus 不可用于 formal run。
- Candidate 之间共享完全相同的Full Review Records、确定性Retrieval Projections、五个role-specific indices和只读Review Memory API；它们可通过各自MemoryProgram形成不同且完整审计的query、检索、hydration与使用策略。
- 旧 run 仍按其记录的 ADR-0002/0007 协议解释；不得把旧 checkpoint 或 Memory snapshot 迁入新协议。
- 新实验必须使用新的 protocol/config/run identity，并将结论限定为固定 Review Corpus 上的 Memory Evolution。
